# Tier 0 公開試玩操作與回饋指南

- 適用版本：AWS Tier 0 公開 HTTPS 試玩
- 建議規模：1 位房主＋2 位玩家，三個獨立瀏覽器或裝置
- 第一輪範圍：一個房間、一個完整回合、最多一次 Bedrock 回合敘事
- 隱私原則：使用暱稱，不輸入真實姓名、Email、電話、公司機密或其他個人資料

公開 HTTPS 網址由專題負責人私下傳送，不寫入 GitHub、問卷或公開文件。房主也只在受測者之間分享當次房號。

## 試玩前檢查

1. 三位受測者使用不同瀏覽器、無痕視窗或裝置。
2. 網頁沒有 certificate warning，頁尾顯示 `AWS Tier 0 公開試玩`。
3. 每位受測者先選一個不含真實身分的暱稱。
4. 第一輪優先由房主手動輸入世界，避免把世界草稿生成額度混入多人流程；若需展示生成，只允許一次正常故事要求。
5. 不進行 Prompt Injection、個資或有害內容測試；安全代表性測試已由 Batch 7、9C、9D 分開完成。

## 三玩家一回合流程

1. 房主建立房間，完成世界設定並私下分享六碼房號。
2. 兩位玩家從首頁加入；三個畫面都應顯示 `3 / 5`。
3. 三位玩家分別建立角色並儲存；Lobby 應顯示 `3 / 3` 角色完成。
4. 房主開始遊戲；三位玩家各自提交一項行動。
5. 房主擲骰；三位玩家分別決定使用或保留星火。
6. 房主結算回合；只允許一次 Bedrock 回合敘事，不因文案偏好重試。
7. 三個畫面應同步進入下一回合，並顯示相同進度、危機與故事敘述。
8. 每位玩家重新整理一次；session、角色與故事狀態都應保留。

若任何一步失敗，先記錄階段與安全錯誤訊息後停止，不重複點擊可能觸發模型的按鈕。

## 回饋項目

請受測者以 1–5 分回答，其中 1 代表非常不同意、5 代表非常同意：

1. 我能在沒有口頭逐步指導的情況下加入房間。
2. 我理解如何建立角色與完成配點。
3. 我理解如何提交行動、選擇屬性與決定星火。
4. 三位玩家的狀態同步速度可以接受。
5. AI 敘事有整合三位玩家的行動，且沒有改寫骰點或規則結果。
6. 重要的 loading、成功與錯誤訊息出現在我正在操作的位置附近。
7. 標題與正文容易閱讀，沒有明顯單字孤行或單行孤頁／孤段。
8. 我願意再玩一個回合。

另收三個簡答：

- 最不直覺的操作是什麼？
- 哪一段文字或畫面最需要改善？
- 如果只能改一件事，你希望改什麼？

只記錄裝置類型與瀏覽器名稱，不記錄姓名、Email、IP、房號、cookie、完整故事文字或自由輸入中的個人資料。

## 停止條件

出現下列任一情況時結束當次試玩，不自行重試模型：

- Certificate warning、登入異常或無法建立可信任 HTTPS。
- 多位玩家持續看到不同 canonical state。
- 同一操作重複扣除次數、重複擲骰或重複結算。
- 公開頁面顯示 stack trace、AWS 原始錯誤、ARN、secret 或其他敏感資訊。
- AI 回覆出現個資、有害內容或明顯偏離既定世界。
- Budget／credits 告警或 AWS service health 異常。

## 報告證據

- 保存三玩家 `3 / 3`、三項行動、骰點／星火、回合結算與 refresh persistence 的去識別化畫面。
- 活動中的房號先遮罩；只有房間已刪除或到期、代碼不再可用時，才可保留房號作為隨機代碼設計證據。
- 截圖不可包含 public IP、account ID、ARN、resource ID、Email、cookie、token 或真實姓名。
- 報告只彙整完成率、1–5 分分布、常見阻礙與優先改善項目，不保存受測者身分。
