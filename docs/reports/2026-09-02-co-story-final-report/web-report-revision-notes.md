### 09｜自動部署

- 主標：
  - `可驗證、可回復`
  - `核准後自動上線`
- 說明：提交版本後，測試、建置、安全掃描與正式環境更新依固定流程執行；工程師只需核准正式發布，系統會驗證上線結果，失敗時回復已驗證版本。
- 自動部署前：本機封裝、S3 上傳、SSM 連入主機、驗證安裝、切換服務、人工檢查。
- 自動部署後：程式測試、正式環境核准、OIDC 短期權限、ARM64 建置、ECR 保存、exact digest 掃描、SSM 更新、健康檢查與回復。

- 已有自動發布樣本：建置與掃描中位數 `126 秒`；SSM 發布中位數 `27 秒`；含核准的端到端中位數 `235 秒`。歷史人工流程沒有一致時間戳，不回推節省分鐘數。

### 10｜安全邊界

### Current production 必須呈現

- 玩家瀏覽器經 Internet Gateway 與 public route 進入 public app subnet 的 EC2。
- Public EC2 承載 Nginx、Web、FastAPI API 與 Publisher responsibilities。
- Private compute subnet 內有兩台無 public IPv4、無 inbound 的 Story Worker；兩台位於同一 Availability Zone。
- Private data subnets／DB subnet group 內是 RDS for PostgreSQL canonical state。
- NAT Gateway 位於 public subnet，提供 private Worker 呼叫 AWS public endpoints 的 outbound 路徑。
- SQS／DLQ、Bedrock、ECR、CloudWatch 與 Systems Manager 位於 VPC 邊界外，標示為 AWS managed services。
- Web SG 與 Worker SG 只經 TLS PostgreSQL `5432` 連到 DB SG。
- GitHub Actions OIDC、人工核准、ECR 與 SSM 是 delivery／operations control plane，不與玩家資料流混在線上。

### 製圖規則

- VPC、public subnet、private compute subnet、private data subnets／DB subnet group必須具有完整可辨識的邊界。
- 採分層或固定正交軌道；線條保持連續，不能穿過節點、標題、備註或其他線路。
- 箭頭在節點邊框前結束，方向與資料流一致，不以拉伸圖形製造變形箭頭。
- 玩家流量、佇列工作、資料交易、模型推論與維運控制直接在線路旁標示，不依賴小型全域圖例。
- 每個節點最多兩層文字：服務名稱與一個關鍵狀態。協定、限制與證據放入大型 callout。
- 1920×1080 投影基準下，架構節點與備註至少 `22–24 px`。
- 同一演進序列保留主要節點座標，透過增添服務與拆分責任表達演進。
- 每個架構狀態都要能獨立停駐截圖，並提供 `prefers-reduced-motion` 靜態版本。
