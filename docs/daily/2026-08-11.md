# 2026-08-11 PostgreSQL 持久化主線

## 排程依據

8/10 的 Session Continue、正式 deep routes 與三玩家完整單回合 E2E 已完成。依 8/10 文件核准的「超前後基礎順序」，下一個 release-gate 是 PostgreSQL repository contract 與 process restart persistence。

本階段只使用本機環境，不登入或修改 AWS。Docker CLI 已安裝，但 2026-08-10 盤點時 Docker daemon 尚未啟動；開始 PostgreSQL integration 前需先啟動 Docker Desktop。

## Model Routing

| 工作 | 模型路由 | 原因 |
| --- | --- | --- |
| Repository／transaction 邊界與 ADR final decision | Sol | 影響資料模型、跨 process 一致性與未來 RDS 遷移 |
| Contract tests、migration、adapter、composition、restart test | Terra | 主要為 coding、tests、debugging 與 implementation |
| 檔案盤點、測試摘要、證據格式與 cleanup | Luna；不可用時 Terra low | 低風險整理工作 |

不為湊比例切換模型；只有資料邊界衝突或重大 persistence bug 才再次使用 Sol。

## P0：當日必須完成

### 1. Persistence decision gate

- 建立 PostgreSQL repository ADR，明確記錄：
  - 小型專案採 aggregate JSONB＋必要索引欄位，或採正規化 tables 的理由。
  - `room_id`、唯一 `room_code`、`version`、timestamps 與刪除策略。
  - Tier 0 單 process 邊界，以及未來多 process 的 transaction／optimistic locking 演進點。
  - 本機 PostgreSQL 與未來 private RDS 使用同一 adapter contract。
- 不在 ADR 核准前直接撰寫 PostgreSQL production adapter。

### 2. Baseline 與 Red repository contract

- 確認工作樹乾淨，Backend `45 passed`、Frontend `58 passed`。
- 建立 Memory／PostgreSQL 共用 contract tests，至少涵蓋：
  - `save → get` 完整 round-trip。
  - `get_by_code` 與不存在資料。
  - 再次儲存更新 version 與完整 aggregate。
  - room、players、characters、world、round、dice results、story entries、session hashes 均不遺失。
- 先執行 PostgreSQL contract，確認因 adapter／schema 尚不存在而 Red；不得以 Docker 未啟動或 import error 冒充 Red。

### 3. Schema、migration 與 PostgreSQL adapter Green

- 使用本機 PostgreSQL 容器；不得把真實密碼或 `DATABASE_URL` commit。
- migration 必須能從空資料庫建立 schema，並可重複檢查目前版本。
- 加入最小 PostgreSQL driver 與 `PostgresRoomRepository`。
- App composition：未設定 `DATABASE_URL` 時維持 Memory；明確設定時才使用 PostgreSQL。
- 不在此切片加入 AWS RDS、Docker production image、UI 優化或 unrelated refactor。

### 4. Process restart persistence

- 以正式 API 建立房間並保存至少：玩家、角色、世界、回合、骰點結果與故事。
- 停止第一個 FastAPI process，以同一 PostgreSQL 啟動第二個 process。
- 保留既有 session cookies，驗證 `GET /api/v1/rooms/current` 可恢復相同資料。
- 驗證 restart 不會重複建立房間、回合或故事。

### 5. Regression、sensitivity 與證據

- Backend、Frontend、Memory contract、PostgreSQL contract 與 restart integration 全綠。
- 暫時破壞一個關鍵 serialization／version 欄位，證明 contract test 會失敗後立即還原。
- 保存 Red／Green／Refactor、migration、restart 與本機容器清理證據。
- 更新 README、部署紀錄、Test Plan 與 CURRENT。
- 測試完成後停止並移除本機 PostgreSQL 測試容器；確認沒有 AWS 費用。

## P0 完成定義

- Memory 與 PostgreSQL 通過同一 repository contract。
- 空資料庫 migration 成功。
- FastAPI process restart 後，room、players、characters、round、results、story 與 session ownership 仍可恢復。
- 完整 regression 全綠且工作樹乾淨。
- 沒有 secret、測試密碼、資料庫 dump 或暫存 volume 被 commit。

未同時滿足以上條件，不得標示 persistence 完成，也不得把「同 process refresh 成功」當作 restart persistence。

## 完成 P0 後才前移

若 PostgreSQL persistence 全部通過，下一個基礎切片為 LLM failure recovery：

1. 先以 Red tests 定義 timeout、throttling、schema invalid、內容拒絕。
2. 驗證 retry／deterministic fallback 不改寫 canonical rules state。
3. 再處理 Polling offline／reconnected；不先進行動畫、配色或大型重構。

## 停止條件

- Docker daemon 無法啟動，且無真實 PostgreSQL 測試環境。
- ADR 尚未解決 aggregate schema 或 transaction 邊界。
- Red 由環境／fixture／import 錯誤造成，而非缺少目標行為。
- Migration 或 restart test 會刪除非本專題、非測試用資料庫或 volume。
- 發現需要 AWS 寫入；立即停止並另走成本與安全關卡。
